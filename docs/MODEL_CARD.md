# Offline classifier model card — vscode-tfidf-v1

This card describes the optional scikit-learn classifier. The dashboard's automatic multi-label analysis uses Groq; see [AI_LABELS.md](AI_LABELS.md).

**Status:** implemented, trained and evaluated locally on real public snapshots, saved/reload-verified and served locally. Not validated with maintainers or hosted in the cloud. Intended use: assist a person triaging VS Code-style public software reports; no automatic source actions.

**Inputs:** title and body only. Pipeline: deterministic template cleanup → word TF-IDF → logistic regression. No source labels, review labels, assignees, issue state, closing reason, comments or later metadata are features. Dataset: `dataset-66cb4613b0925284`, mapping `labels-v1`, seed 42.

Three configurations were fitted on training data. Validation macro-F1 selected word unigrams, maximum 20,000 features, minimum frequency 1, C=1, balanced class weights. Selected model was not refitted on validation data. The baseline is `DummyClassifier(strategy=most_frequent)` fitted on training labels. Test results were computed after settings and threshold were fixed, with no test-driven retuning.

Enhancement support is only 14 test examples, so its estimate is particularly fragile. Complete per-class metrics and confusion matrix are in `docs/EVALUATION.md` and `evidence/classification-evaluation.json`.

**Review threshold:** 0.55, selected only on validation data. Policy: maximize coverage subject to at least 10 unflagged examples and validation accuracy ≥0.85; otherwise maximize accuracy × sqrt(coverage). At the chosen cutoff, validation unflagged accuracy is 0.8533 on 75 examples. Test flags 55.03%; unflagged accuracy is 0.8816 on 76 examples and unflagged macro-F1 is 0.6923. These subset results are not overall model performance. Scores have not been calibrated.

**Failure modes:** question versus request overlap, existing-behavior versus enhancement ambiguity, short context, label noise, imbalanced and changing class prevalence, project-specific vocabulary, old data and incomplete template detection. The observed question recall is only 0.3448. Human judgment is necessary even for high scores. Missing models leave manual categorization available.

**Historical limitation:** chronological retrospective evaluation using collected snapshots; text/labels may have been edited or assigned after creation. Neither label availability nor exact text at a historical cutoff is proven. No strict historical deployment simulation or cross-repository quality claim is made.

**Artifacts:** trusted local Pipeline and baseline, mapping, frozen manifest, exact dependencies/lock, configuration, splits, metrics, errors, threshold candidates, random seed and generated card. The API verifies checksum and scikit-learn version. Joblib can execute code; load only artifacts generated by this project and controlled by the installation owner.

**Retrieval model:** `sentence-transformers/all-MiniLM-L6-v2`, revision `c9745ed1d9f207416be6d2e6f8de32d1f16199bf`, Apache-2.0; 384 normalized dimensions, first 256 wordpieces, CPU execution. This is a separate text similarity capability, not the category classifier. Relevance quality is pending genuine pooled judgments.

**Retraining:** explicitly synchronize, freeze a new version, inspect labels/duplicates/support, train, review sealed validation/test evidence, then activate and batch-predict. Never overwrite an experiment version. `review-dataset` exports future human labels and excludes validation/test GitHub issue identities from every saved manifest, including later revisions of those issues. It does not automatically merge or train that export. Preserve all old manifests across deployments; removing them removes that exclusion history. Do not recycle old test examples into training and report on the old test set.
